# Исходники сцен: формат

Сцена — это файл `scripts/dialogs/scenes/<имя>.py` с объектом `SCENE`. Из него
`scripts/dialogs/build.py` собирает диалог, таймлайн с постановкой, сцену, записи
банков, тексты EN/RU, реакции одобрения и новые флаги (подробно — `docs/STAGING.md`).
Новую сцену нужно добавить в список `SCENES` в `build.py`; главы `scenes/chNN_*.py`, места (`scenes/places.py`) и фразы в пути (`scenes/travel.py`) подхватываются сами.

Формат повторяет сценарий из `design/dialogs/*.md`: блоки реплик Альфиры, варианты
героя, переходы. Пример — `scenes/recruitment.py` (сцена A, 13 вариантов, проверка,
общие меню, озвученные реплики).

## Сцена

```python
from dsl import ALFIRA, PLAYER, Join, Scene, check, new_flag, opt, outcome, say, voice
from vanilla import DC, F, NESTED, T

SCENE = Scene(
    name="ALFSV_Alfira_Recruitment",           # имя ресурса и файлов
    dialog_id="009896a5-…",                     # ID в банке диалогов; на него ссылается Osiris, не менять
    base="DEN_Bard_InParty",                    # ванильный диалог: его сцена, камеры, актёры
    voice_from=["CAMP_DarkUrge_MurderOfAlfira_CFM_AlfiraArrives", …],  # где искать озвученные реплики
    nested=[NESTED.SwapRecruitment],            # вложенные диалоги (меню замены при полном отряде)
)
S = SCENE
```

## Блоки

| Вызов | Что это |
|---|---|
| `S.greeting("id", строки…, when=[условия], <переход>)` | Приветствие (корень). Порядок вызовов = приоритет: игра берёт первое, чьи условия выполнены |
| `S.block("id", строки…, <переход>, when=[…])` | Реплики Альфиры подряд; `when` — условия (для альтернатив `go=[…]`) |
| `S.chapter_entries()` | Только в `inparty.py`: здесь встают входы в главы (см. «Главы разговоров») |
| `S.menu("id", варианты…)` | Меню вариантов без реплики. На него ведут `go="id"` из разных мест: это одни и те же узлы, поэтому «один раз» и петли работают как в игре |

**Переход** — ровно один из аргументов:
- `go="A3"` — дальше блок A3 (если A3 — меню, сразу его варианты);
- `go=["C5a", "C5b"]` — альтернативы: игра берёт первый блок, чьи условия `S.block(..., when=[…])`
  выполнены. Если у последнего есть условия, build добавит в конец пустой узел «конец» (так у Larian
  делается «или»: два узла с разными условиями);
- `choices=[opt(…), …]` — варианты прямо здесь;
- `end=True` — конец диалога;
- `join=Join(...)` — вступление в отряд (см. ниже).

У `greeting`/`block` есть `set=[…]` — флаги на последней реплике блока.

## Реплики Альфиры

```python
say("Stop it. No - actually, don't stop…", "Перестань. Нет — вообще-то не переставай…",
    emo="happy/2>happy", shot="alfira_close", note="(краснеет)")
voice("h4d653a62g29e7g4ce3g813fg184db5a4e691")      # её реплика из игры: голос, текст и перевод Larian
```

- `*курсив*` → `<i>курсив</i>` игры. Ремарки («(краснеет)») в текст не пишутся — их роль
  играет `emo`; сам текст ремарки можно оставить в `note` для людей.
- Род обращения к герою в русском: `{мужской|женский}` — «Ты {спел|спела}». Мужская форма
  идёт в `AlfiraSecondVerse_ru.xml`, женская — в `AlfiraSecondVerse_ru_to_F.xml`.
- `emo` — эмоции лица по ходу реплики: `"happy"`, `"surprise>happy"` (делят фазу поровну),
  `"happy/2"` (вариация 2), или список `[(0.0, "fear"), (2.5, "sad/1")]` (секунды).
  Имена: neutral, happy, thinking, angry, fear, sad, surprise, disgust, sleeping, dead,
  confusion, pain (коды — из `Public/Shared/Animation/Emotions.lsf`, сверяются при сборке).
- `shot` — план камеры: `alfira` (из-за плеча героя, по умолчанию), `alfira_close`
  (крупный план), `player` (на героя).
- `voice(handle)` — handle ищется в диалогах `voice_from`. Постановка (эмоции, взгляды,
  позы, планы камеры) берётся из ванильной фазы этой реплики; `emo`/`shot` не нужны.
- У любой реплики: `set=[…]` (флаги), `approve=±N` (одобрение Альфиры).

### Ремарки рассказчика

```python
narrate("A pause. She looks down at her boots.", "Пауза. Она смотрит на свои сапоги.",
        emo="sad", shot="alfira_close")
```

Действие без слов (ремарка сценария) — так, как это делает игра: узел рассказчика (speaker −666),
текст в звёздочках (`*…*` — так в loca игры, build добавит их сам), без озвучки. В таймлайн
добавляется актёр рассказчика (тот же, что у Larian, `a346318f-…`); `emo` — лицо Альфиры,
`shot` — план камеры. Своих анимаций нет (этап 9): ремарка только описывает действие.

## Варианты героя

```python
opt("Почему именно со мной?", "Why me, of all people?",   # русский, английский
    when=[T.BARD(PLAYER)],          # условия показа
    once=True,                      # показать один раз (ShowOnce игры)
    approve=+2, set=[SPARK(PLAYER)],
    reply=[voice("h1ab…"), voice("h2b0…")],                # её ответ (может не быть)
    go="A4")                        # переход после ответа
```

Проверка навыка (ActiveRoll, как в игре — вариант показывается один раз):

```python
check("*Присмотреться к ней внимательнее.*", "*Look at her more closely.*",
      skill="Insight", ability="Wisdom", dc=DC.Act1_Medium,
      success=outcome(approve=+2, reply=[say(…), voice(…)], go="A4"),
      failure=outcome(reply=[say(…)], go="A4"))
```

## Флаги и условия

- Ванильные — в `vanilla.py` (`F.FinishedSong`, `T.BARD`, …) с именем, типом и uuid из данных
  игры. При каждой сборке `build.py` сверяет имя и тип с файлами `Flags`/`Tags` игры.
- Новые: `new_flag("ALFSV_Имя", "Global" | "Object" | "Dialog", "описание")`; uuid выдаётся
  детерминированно от имени, файл флага пишется в `Public/_MOD_/Flags/`.
- Запись: глобальный `F.X.on` / `F.X.off`; на персонаже `FLAG(ALFIRA)` / `FLAG(PLAYER)`,
  снять — `FLAG(ALFIRA, False)`. «Dialog» хранится на персонаже (как `DEN_TieflingBard_HasMet`).
- В `when` — условия (все должны выполняться), в `set` — что поставить/снять.
- Реплика героя с родом по-русски («Рад / Рада») — два варианта с условием по тегу пола героя:
  `when=[~T.FEMALE(PLAYER)]` и `when=[T.FEMALE(PLAYER)]` (так делает игра, 254 диалога). `{м|ж}`
  работает только в репликах Альфиры: это род *обращения к герою* (`…_ru_to_F.xml`).

## Вступление в отряд

```python
Join(nested=NESTED.SwapRecruitment,                       # меню замены при полном отряде
     to_camp_line=say("I'll find your camp…", "Я найду твой лагерь…"),  # если герой отправил её в лагерь
     to_camp_flag=F.SwapToCamp,
     reply=None)                                          # реплика при вступлении (или узел без текста)
```

Даёт ту же структуру, что у вербовки Уилла и Лаэ'зель: при `GEN_MaxPlayerCountReached` —
вложенный диалог замены, иначе узел, ставящий `OriginAddToParty` на Альфиру.

## Главы разговоров (этап 4)

Глава — отдельная сцена `scenes/chNN_<имя>.py` (NN — номер главы, файлы подхватываются сами) с
объявлением `chapter(...)`:

```python
from dsl import chapter
from vanilla import F

CH = chapter(2, "Лютня",                    # номер = порядок в очереди (см. «Очередь глав»)
             after_rest=True,               # открыться после долгого отдыха (False — сразу)
             story=[F.Something.on],        # все условия сюжета: глобальные флаги или osi("…"); проверяет Osiris
             story_any=[F.A.on, osi("…")],  # хотя бы одно из условий (например, «первая крупная победа»)
             optional=False,                # необязательная: без выполненного story очередь не держит
             act=None,                      # только в этом акте (dsl.ACT_LEVELS); только у необязательной
             expire=False,                  # снят флаг из story, а глава не сыграна — перестаёт ждать
             hub=True,                      # вход в разговоре в отряде (False — диалог запускает свой Osiris)
             when_any=[[A(PLAYER)], [B(PLAYER)]],  # вход «или»: по корню на вариант (к when)
             priority=0,                    # в одной проверке раньше открывается глава с бо́льшим приоритетом
             when=[F.CampNight.on],         # условия входа при каждом разговоре (флаги диалога)
             approval=10)                   # мин. одобрение собеседника (Approval_AtLeast_10_For_Sp1)

SCENE = Scene(name="ALFSV_Alfira_Ch02_Lute", dialog_id="<uuid4>", base="DEN_Bard_InParty",
              voice_from=[…], chapter=CH)
S = SCENE
S.greeting("G1", …)                         # как в любой сцене
…
opt("…", "…", set=[CH.done], go="…")        # где глава считается сыгранной
```

Что делает build:
- два глобальных флага главы: `ALFSV_ChapterNN_Available` и `ALFSV_ChapterNN_Done`;
- goal Osiris `Mods/_MOD_/Story/RawFiles/Goals/ALFSV_Chapters.txt` (генерируется, руками не
  править) — очередь глав, см. ниже;
- в разговоре в отряде (`inparty.py`, место — `S.chapter_entries()`: после холодной реплики, до
  ротации приветствий) для каждой главы — корень без текста с условиями `Available`, `!Done`,
  `when`, порогом одобрения, под ним узел `Nested Dialog` на диалог главы и конец. Так же
  устроены главы Шэдоухарт (`ShadowHeart_InParty2` → `*_Nested_*Chapter`). Пока новой главы
  нет, играет ротация приветствий;
- диалог главы — обычная сцена (свой таймлайн), ID — в `childResources` разговора в отряде.

### Очередь глав

Глава **ждёт**, пока она `Available` и не `Done`. Глава N открывается (`…_Available`) на проверке,
если одновременно:
1. Альфира — спутница; глава ещё не открыта и не сыграна;
2. **никакая глава не ждёт** (`QRY_ALFSV_Chapters_Waiting`);
3. сыграны все **обязательные** главы с меньшими номерами; необязательные в этом списке не участвуют;
4. выполнены все `story` и хотя бы одно из `story_any`;
5. если `act` — сейчас этот акт (`DB_CurrentLevel` из `dsl.ACT_LEVELS`: акт 1 — `WLD_Main_A`, `CRE_Main_A`);
6. если `after_rest` — это проверка после долгого отдыха.

Проверки: после каждого долгого отдыха (`PROC_LongRest`, `after_rest` выполнено), при вербовке, когда
сыграна глава, когда поставлен флаг из `story` главы без `after_rest`, в начале уровня (если у глав есть
`act`) и в INIT goal. Правила глав идут по номерам: первая открывшаяся глава ждёт, и остальные в той
же проверке уже не открываются — **одна новая глава за проверку** (за отдых).

Отсюда семантика `optional=True`: необязательная глава, у которой к проверке не выполнено условие
сюжета, очередь **не держит** — следующие главы открываются без неё. Когда её условие наступит позже,
она откроется на ближайшей проверке (после отдыха, если `after_rest`), где никакая другая глава не ждёт;
номер у неё прежний, но идёт она уже после более поздних глав. Обязательная глава с невыполненным
`story` держит все главы после себя (как раньше).

Необязательная глава перестаёт ждать (снимается `Available`, `Done` не ставится — открыться снова она
может, только если условия опять выполнятся):
- `act=N` — если открыта, но не сыграна, а акт кончился (проверка на новом уровне);
- `expire=True` — когда снят флаг из её `story` (так глава-событие «Праздник» не держит очередь, если
  ночь прошла без разговора).

Порог `approval` у необязательной главы проверяется и при открытии (у кого-то из аватаров одобрение N+,
`QRY_ALFSV_Chapters_Approval`): иначе она ждала бы одобрения, держа очередь. `priority` — порядок правил в
проверке (глава 5 «Утро после» открывается на утро после праздника раньше других). `when_any` — вход «или»:
по корню без текста на каждый список условий, под ними один вложенный диалог (глава 8: роман открыт / «спроси
снова» / «отложено»).

`hub=False` — глава-событие: входа в разговоре в отряде нет, диалог главы запускает её Osiris
(глава 4 — `ALFSV_Companion.txt`). Флаги `Available`/`Done` и очередь — те же.

### Сцена на троих

`Scene(..., other="<uuid персонажа>", other_name="Лакрисса")` и основа с тремя спикерами (Альфира,
третий, герой) — например `HAV_AlfiraTale_ReunionWithFlirty`. Build берёт номера слотов спикеров из
основы (флаги `FLAG(PLAYER)` и т. п. получают правильный `paramval`). Реплика третьего —
`say(en, ru, speaker=OTHER)`: только текст, фаза по шаблону основы, эмоции — на его лице, план `other`
(из-за плеча героя) или `other_close`. Камеры subject2 берутся из общей сцены основы
(`bnz_standing_Px2`); движения локальных камер основы в шаблонную фазу не копируются. Модуль сцены
может отдать build ещё диалоги (`EXTRA_SCENES = [...]`) и флаги, которые ставит только Osiris
(`OSIRIS_FLAGS = [...]`).

`CH.done` ставит сама глава там, где она считается сыгранной (обычно первый содержательный ответ
героя). Выход раньше (например, «Завтра рано вставать») главу не закрывает — она предлагается
снова. Отладка из консоли SE: `Osi.PROC_ALFSV_Debug_UnlockChapter()` — как будто прошёл отдых.

Порядок добавления главы: сценарий согласован → файл `scenes/chNN_*.py` → `build_pak.py` →
`check_story.py` (goal глав изменился) → `validate.py` → `tree.py` → повысить версию мода
(Osiris изменился) → проверка в игре.

## Реплики над головой: места и путь (этап 5)

Короткие реплики без остановки игры — AD (automated dialog): текст над головой Альфиры, у её
озвученных реплик — голос игры. Механизм — `scripts/dialogs/ads.py`, подробности и схема —
[docs/STAGING.md §5b](../../docs/STAGING.md#5b-реплики-над-головой-ad-этап-5).

**Место** — запись в `scenes/places.py`:

```python
from ads import COLD, NOTCH, ROMANCE, SPARK, place, variant
from dsl import say, voice

place("Monastery", "Обитель Розиморн",                        # ключ (не менять: по нему «уже сказано») и название
      variant(say("...", "...", emo="thinking"), when=[SPARK]),  # варианты по приоритету: 💞 ROMANCE, ✨ SPARK,
      variant(say("...", "...")),                                # ❄️ COLD, 🔁 NOTCH; последний — обычный, без условий
      act=1,
      triggers=["S_CRE_Monastery_SUB_94be6628-ed02-4bdc-9173-5d1b06f26daa"],   # EnteredTrigger(Альфира, …)
      source="…Act1b_Subregions.txt (CRE_Monastery_SUB)")      # откуда взят триггер — для проверки
```

- Запуск — одно из: `triggers=[…]` (любой из списка, что раньше), `flags=[…]` (глобальный флаг игры
  поставлен), `levels=[…]` (начало уровня), `custom="lift"` (особый запуск в `ads.LIFT_BLOCK`).
- Триггер — только тот, что игра сама держит зарегистрированным для отряда: подрегионы
  (`DB_Subregion`/`DB_SubregionMarker` в `Act*_Subregions.txt`), триггеры бесед отряда
  (`PROC_RegisterWorldGossipTrigger`). Свою регистрацию мод не делает.
- Вариант — одна или несколько реплик подряд (`say`/`voice`); ремарки сценария («берёт за руку»)
  над головой не показываются — их роль играет `emo`, текст остаётся в `note`.
- Места без надёжного запуска — в `GAPS` того же файла, с причиной. В игру они не идут.

**Фразы в пути** — `scenes/travel.py`: `travel((реплика, [условия]), …)`. Каждая звучит один раз
(флаг `ALFSV_Travel_NN_Played`), игра берёт первую по порядку подходящую. Добавлять новые — в
конец списка: номер фразы = её флаг в сохранениях.

Build делает из каждого места и из набора фраз в пути AD (`Companions/ADs/ALFSV_AD_*`) и goal
`ALFSV_World.txt`. Порядок: запись → `build_pak.py` → `check_story.py` → `validate.py` →
`tree.py` (`build/dialogs/ALFSV_AD_*.md`) → проверка в игре. Отладка из консоли SE:
`Osi.PROC_ALFSV_Debug_Place("Monastery")`, `Osi.PROC_ALFSV_Debug_Travel()`.

## Сборка и проверка

```
python scripts/dialogs/build.py      # генерация в mod/ (запускается и из build_pak.py)
python scripts/dialogs/validate.py   # ссылки, фазы, круг lsx↔lsf через Divine, сверка с игрой
python scripts/dialogs/tree.py       # дерево диалога в build/dialogs/<сцена>.md для вычитки
```

UUID узлов, handle текстов и id компонентов таймлайна выводятся из ключей (id блока и номер
реплики/варианта), поэтому повторная сборка даёт те же файлы. Если переставить варианты
местами, их UUID поменяются — это безопасно, пока диалог не открыт в сохранении.
