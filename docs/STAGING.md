# Постановка диалогов: конвейер

Статус: **собрано, в игре не проверено.** С 0.4.0 — главы разговоров (§5a) и ремарки рассказчика; с 0.5.0 — реплики
над головой: места и путь (§5b).

Диалоги мода делаются с постановкой, как у Larian: камера, эмоции лица, взгляды, позы.
Источник — описание сцены на Python (`scripts/dialogs/scenes/*.py`, формат —
[scripts/dialogs/README.md](../scripts/dialogs/README.md)), результат — ресурсы игры в `mod/`.
Инструмент — библиотека [bg3moddinglib](https://github.com/0x1amy0urdad/Guidance) (MIT,
автор Really Shadowheart): чтение паков игры через LSLib, объекты диалога, таймлайна и сцены.

## 1. Что нужно на машине

| Что | Где задаётся |
|---|---|
| bg3moddinglib, коммит `2f25d73` (`git clone https://github.com/0x1amy0urdad/Guidance`) | `config/tools.local.json` → `bg3moddinglib_path` (папка `src`), `bg3moddinglib_commit` |
| Окружение библиотеки: LSLib 1.20.3 (скачивает сама с github.com/Norbyte/lslib), индекс ресурсов игры (~1,5 мин при первом запуске), рабочая папка | `bg3moddinglib_env`, по умолчанию `C:/Tools/bg3moddinglib-env` — вне репозитория |
| Python 3.12+, `pip install numpy requests pythonnet` | — (wxpython и pyinstaller библиотеке как модулю не нужны) |
| .NET 8 | уже нужен для `check_story.py` |
| Игра (паки `Data/`) | `game_dir` |

В репозиторий библиотека не копируется. `scripts/dialogs/bg3lib.py` подключает её через
`sys.path` и делает две вещи поверх неё, не меняя её файлов:
- переводит .NET-культуру процесса в инвариантную. Иначе LSLib внутри процесса на русской
  Windows пишет в `.lsx` дроби через запятую, и Divine их потом не читает;
- подменяет её генератор случайных UUID детерминированным. Повторная сборка даёт те же
  файлы: чистые диффы, стабильные ID в сохранениях.

## 2. Как устроена сборка

`python scripts/build_pak.py` сначала запускает генератор (`scripts/dialogs/build.py`,
флаг `--no-generate` его пропускает), потом собирает пак как раньше.

Для каждой сцены генератор делает:

1. **Копию основы.** `bg3_assets.create_new_empty_dialog_from_another(base, …)` берёт
   ванильный диалог-основу (у всех наших сцен это `DEN_Bard_InParty`: Альфира и герой
   один на один, стандартная сцена `bnz_standing_Px1`; о выборе основы — §6). Из копии убираются узлы и фазы,
   остаются список спикеров, актёры таймлайна, камеры, свет и файл сцены (`_Scene`).
   ID диалога — из сцены (`dialog_id`, на него ссылается Osiris), ID таймлайна выводится из имени.
2. **Узлы диалога** по блокам сцены (`dialog_object.create_standard_dialog_node`,
   `create_roll_dialog_node`, свой узел `Nested Dialog`). Общие меню — одни и те же узлы у
   разных родителей, как в диалогах Larian: поэтому работают «один раз» и петли «назад к выбору».
3. **Фаза таймлайна для каждой реплики Альфиры** (`scripts/dialogs/staging.py`):
   - *озвученная реплика игры* (`voice(handle)`) — находится её узел и `TLVoice` в ванильном
     таймлайне (`voice_from`). Из той фазы вырезается окно её реплики: голос (`TLVoice` с
     оригинальными fade и коррекцией головы), эмоции, взгляды, позы Альфиры и героя, планы
     камеры. Актёры переводятся на наших; камеры из общей сцены `bnz_standing_Px1`
     переводятся на такие же камеры с теми же привязками (недостающие добавляются в актёров
     таймлайна и в `DependencyCache`); локальные камеры чужой сцены заменяются стандартным
     планом. Пустые события чужой фазы и всё, что касается других персонажей, не
     переносится — их место занимает шаблонная фаза основы;
   - *текстовая реплика* (`say`) — фаза по шаблону (первая фаза основы с одной репликой
     Альфиры): позы, взгляды друг на друга, эмоции «зрителей», оружие, физика; голос без
     звука; эмоции из сценария; один план камеры (`shot`).
   - *ремарка рассказчика* (`narrate`) — как текстовая реплика, но голос у актёра рассказчика
     (Speaker −666, uuid Larian `a346318f-…`; актёр добавляется в таймлайн один раз), лицо и
     камера — на Альфире.
   Фразы героя фаз не имеют, как в игре. Обработчики боя — по одному на фазу, как у Larian.
4. **Записи банков**: ресурс диалога (`SourceFile`, `childResources` для вложенных диалогов)
   и ресурс таймлайна (`DialogResourceId`, `SourceFile`, `DependencyCache`).
5. **Тексты**: новые реплики — в `AlfiraSecondVerse_en.xml` и `…_ru.xml`, женские формы
   обращения — в `…_ru_to_F.xml`. Озвученные реплики игры в loca мода не пишутся: у них
   handle, текст, перевод и голос игры.

Общие файлы: банк диалогов, банк таймлайнов (`[PAK]_GeneratedDialogTimelines`), реакции
одобрения (по одной на значение: +1, +2, +3, −1), новые флаги, её глобальный персонаж
с одобрением (§4), goal Osiris глав `Story/RawFiles/Goals/ALFSV_Chapters.txt` (§5a) и
`build/dialogs/manifest.json` (список ванильных handle — `build_pak` не требует для них текста
в loca мода; главы и их флаги).

### Что лежит в git, а что нет

| В git (наше) | Не в git, собирается при каждой сборке |
|---|---|
| `scripts/dialogs/scenes/*.py` — источник | `mod/Public/_MOD_/Timeline/` — таймлайны и сцены (камеры, свет, постановка Larian) |
| диалоги `Story/DialogsBinary/**/*.lsx`, банк диалогов, loca, реакции, флаги, goals `ALFSV_Chapters.txt`, `ALFSV_World.txt` | `mod/Public/_MOD_/Content/Generated/` — банк таймлайнов |
| | `mod/Mods/_MOD_/Globals/` — её персонаж из игры с `HasPlayerApprovalRating` |

Файлы в `mod/`, которыми владеет генератор (`Story/DialogsBinary`, `Timeline`, `Content`,
`ApprovalRatings`, `Flags`, `Globals`), руками не правятся: перед записью папки очищаются.

### Длительность реплик без озвучки

Фаза текстовой реплики = длина текста (большего из EN/RU) / 14 символов в секунду + 0,6 с,
от 2,5 до 14 с (`READ_CPS`, `MIN/MAX_TEXT_PHASE` в `staging.py`). `TLVoice` в фазе есть, как
у всех реплик, но звука для нового handle нет: игра показывает субтитр на длину фазы.
Сейчас это 25 из 46 фаз сцены A и 2 из 7 фаз разговора в отряде.

## 3. Проверки без игры

```
python scripts/check_story.py         # goals мода компилятором LSLib
python scripts/build_pak.py           # генерация + пак
python scripts/dialogs/validate.py    # проверка сгенерированного
python scripts/dialogs/tree.py        # дерево диалогов в build/dialogs/*.md
```

`build.py` перед генерацией сверяет с данными игры: коды эмоций (`Emotions.lsf`), имена и типы
всех ванильных флагов и тегов сцен, наличие озвучки каждой реплики `voice()` в VoiceMeta Альфиры.

`validate.py` проверяет:
- диалог: дети, корни, вложенные диалоги в банке, реакции, типы новых флагов, тексты на всех языках;
- таймлайн ↔ диалог: у каждой реплики Альфиры есть фаза и `TLVoice`; компоненты и ключи в
  границах своей фазы; актёры, камеры и цели взгляда описаны среди актёров; длительность
  эффекта равна сумме фаз; ID таймлайна и диалога в банках сходятся;
- круг через Divine: каждый ресурс `lsx → lsf → lsx` без ошибок и без изменений дерева.
  Исключения: `_Scene.lsx` (формат редактора с `mat4x4`, LSLib не конвертирует и ванильный)
  сверяется с оригиналом игры — отличается только `Identifier`; у реакций одобрения в lsf
  меняется только имя региона (они и у игры, и у нас идут в пак как `.lsx`);
- сверку структуры с ванильной основой. Сейчас у игры есть, а у нас нет только: `GroupID/GroupIndex`
  узлов (не используем), `ApprovalRatingID` в разговоре в отряде (там нет реакций),
  `HeadPitch/HeadYawCorrection` у голоса (есть лишь у одной реплики основы, в вербовке её нет) и
  скомпилированные снимки `CompiledNodeSnapshots` (их убирает и библиотека: игра строит их сама).

- У Хальсина, Минтары, Минска и Джахейры одобрение включено атрибутом
  `HasPlayerApprovalRating` в их глобальном персонаже (`Globals/<уровень>/Characters`). В

- Реакции диалогов (`ApprovalRatingID` узла → `ApprovalRatings/Reactions/<uuid>.lsx`) ключуют
  спутника по UUID Origin «Alfira» `38357c93-b437-4f03-88d0-a67bd4c0e3e9`.
- Стартовое одобрение +20 (песня закончена, лютню не крали) — в `ALFSV_Companion.txt` при
  первой вербовке, как у Джахейры: `ChangeApprovalRating(…, 1, 20, _)` один раз на аватара.
- Пороги для диалогов даёт игра: флаги `Approval_AtLeast_N_For_SpK` на спутнике
  (`_GLO_Shared_Origins.txt`). Холодная реплика в отряде стоит на `Approval_AtLeast_0_For_Sp1 = False`.

## 5. Как добавить сцену

1. Сцена согласована в `design/dialogs/*.md`.
2. Новый файл `scripts/dialogs/scenes/<имя>.py` по образцу `recruitment.py`: `SCENE = Scene(...)`,
   новый `dialog_id` (`python -c "import uuid; print(uuid.uuid4())"`), основа (`base`) —
   ванильный диалог с тем же составом спикеров; `voice_from` — диалоги, откуда берутся её
   озвученные реплики (handle — в `reports/dialogs/*.md` и loca игры).
3. Имя модуля — в `SCENES` в `scripts/dialogs/build.py`.
4. Если сцену открывает Osiris — ID ресурса из `dialog_id` в goal (`DB_Dialogs`,
   `QRY_SelectCustomDialog`…), затем `check_story.py` и повышение версии мода.
5. `build_pak.py`, `validate.py`, `tree.py`, вычитка дерева, проверка в игре.

Для диалога с другим составом (например, беседа отряда) нужна основа с таким же набором
спикеров: генератор находит актёров Альфиры и героя по списку спикеров основы.

## 5a. Главы разговоров (этап 4)

Глава — сцена `scenes/chNN_*.py` с объявлением `chapter(...)`; формат и порядок добавления —
[scripts/dialogs/README.md](../scripts/dialogs/README.md#главы-разговоров-этап-4). Коротко:

```
разговор в отряде (ALFSV_Alfira_InParty)
  ├─ холодная реплика (одобрение < 0)                 → меню отряда
  ├─ [вход в главу N] корень без текста: Available, !Done, when, порог одобрения
  │     └─ Nested Dialog → ALFSV_Alfira_ChNN_… (свой таймлайн) → конец
  └─ ротация озвученных приветствий                   → меню отряда
Osiris (ALFSV_Chapters.txt, генерируется):
  PROC_LongRest / вербовка / FlagSet(Done главы) / FlagSet(story главы без отдыха) / начало уровня / INIT
    → PROC_ALFSV_Chapters_Unlock(отдых?)
  глава N: спутница, !Available(N), !Done(N), никто не ждёт, Done(обязательных < N),
           [отдых], [story], [story_any], [акт] → Available(N)
  необязательная: кончился акт / снят флаг story (expire), а Done нет → !Available(N)
```

**Необязательные главы.** Глава «ждёт», пока она `Available` и не `Done`; пока ждёт хоть одна,
новые не открываются — одна новая глава за проверку. `optional=True`: глава, у которой не выполнено
условие сюжета, очередь не держит, более поздние главы открываются без неё; когда условие наступит,
она откроется на ближайшей проверке, где никто не ждёт. `act=N` ограничивает главу актом
(`DB_CurrentLevel`: акт 1 — `WLD_Main_A`, `CRE_Main_A`, как делит игра в `GLO_Pixie.txt`); открытая, но
не сыгранная глава после конца акта перестаёт ждать. `expire=True` — то же, когда снят флаг из `story`.
`hub=False` — глава-событие без входа в разговоре в отряде (глава 4, праздник). Подробно —
[scripts/dialogs/README.md, «Очередь глав»](../scripts/dialogs/README.md#очередь-глав).
Сцена на троих (`Scene.other`, `say(..., speaker=OTHER)`) — там же, «Сцена на троих».

Флаги `Available`/`Done` глобальные (одна Альфира на игру). Условия, которые зависят от
собеседника (одобрение, пол, теги, флаги на герое), — в `when`/`approval`, они проверяются при
каждом разговоре. Условия-события сюжета — в `story`, их проверяет Osiris в момент открытия.

## 5b. Реплики над головой (AD, этап 5)

Реплики на местах и фразы в пути — AD (automated dialog): игра показывает реплику над головой
говорящего и не останавливает игру. Формат описаний — [scripts/dialogs/README.md](../scripts/dialogs/README.md#реплики-над-головой-места-и-путь-этап-5),
код — `scripts/dialogs/ads.py`.

Как это у Larian (по данным игры):
- реакция спутника на место — AD категории «Voice bark» с одним спикером-спутником, запуск из
  Osiris `PROC_TryStartAD(диалог, спутник)` (`IRN_IronThrone_AD_WyllSeesDeadRavengard`,
  `Act3_OriginMoments_Wyll.txt`); `PROC_TryStartAD` требует у ресурса `automated = True`
  (`__GLOBAL_Dialogs.txt`, `QRY_TryStartAD_CheckAutomated`);
- у AD есть таймлайн: фаза на реплику, в ней `TLVoice` и эмоции, без сцены и камер
  (`CAMP_Bard_AD`, `SCE_AD_Alfira`);
- повторяемая болтовня — категория «Repeated automated NPC Dialog»: игра запускает тот же AD
  снова, а корни с флагами выбирают следующую фразу (`CAMP_Bard_AD`).

Как это у нас:

```
scenes/places.py: place(ключ, варианты…, triggers | flags | levels | custom)
scenes/travel.py: travel((реплика, [условия]), …)
      │ build.py
      ├─ AD на каждое место: основа SCE_AD_Alfira (один спикер — Альфира), категория «Voice bark»,
      │  корни = варианты по приоритету 💞 > ✨ > ❄️ > обычный (условия — флаги MOOD на Альфире)
      ├─ AD фраз в пути: категория «Repeated automated NPC Dialog», корень на фразу, флаг «сказано»
      └─ goal ALFSV_World.txt (генерируется)
Osiris:
  событие (EnteredTrigger(Альфира, триггер) | FlagSet | LevelGameplayStarted | фуникулёр)
    → ожидание до 60 с (бой, разговор, катсцена) → PROC_ALFSV_AD_SetMood → PROC_TryStartAD
    → AutomatedDialogStarted → «сказано» (DB_ALFSV_PlaceDone). Один AD за раз.
  таймер 3–6 мин → фраза в пути, если она в отряде, не в лагере, свободна и мест в ожидании нет.
```

- **Настроение.** Флаги героя (искра, роман, зарубка) и одобрение AD проверить не может: у него один
  спикер. Перед каждым запуском Osiris ставит на Альфиру флаги `ALFSV_AD_Romance / _Spark / _Cold /
  _Warm / _NotchCity` по всем аватарам (`GetFlag` на герое, `DB_ApprovalRating`): роман — у кого-то
  `ALFSV_Romance_Started`; искра — `ALFSV_Romance_Spark` или роман; холодно — одобрение ниже 0;
  тепло — 40 и выше; зарубка — `ALFSV_Notch_City`.
- **Триггеры.** Только те, что игра держит зарегистрированными для отряда сама: подрегионы
  (`DB_Subregion` → `_GLOBAL_Subregions.txt`, `PROC_TriggerRegisterForParty`) и триггеры бесед отряда
  (`PROC_RegisterWorldGossipTrigger` → `GLO_WorldGossip.txt`, не снимаются). Своя регистрация
  запустила бы чужие правила `EnteredTrigger` на тех же триггерах, поэтому её нет.
- **Данные — правилами.** Список мест вставляет `PROC_ALFSV_World_Data` в INIT и при каждом
  `LevelGameplayStarted`: новые места доходят до начатых игр (INIT существующего goal не
  перезапускается, как и у глав).
- **Фуникулёр Яслей Иллек** — три AD по ходу рейса (`ads.LIFT_BLOCK`): начало — наше правило на
  ванильный `PROC_CRE_Dungeon_ElevatorMove` платформы `S_LTN_PLT_CRE_RailLift_000`, если Альфира в
  10 м от рычага кабины `S_CRE_ElevatorLever_000`; середина — опрос раз в секунду: до точки
  назначения меньше половины начального расстояния; верх — `PlatformMovementFinished(…,
  "CRE_Dungeon_ElevatorMoved")` (`Act1b_CRE_Exterior.txt`).
- **Лифт Гримфорджа и ясная ночь** — тоже особые запуски (`ads.GRYMFORGE_LIFT_BLOCK`,
  `ads.CLEAR_NIGHT_BLOCK`): прибытие после смены уровня через ванильный хук
  `PROC_GLO_LevelSwap_LeavingFromTo` и первый свободный вечер в лесном лагере `WLDMAIN`. Подробно —
  [STAGE5.md §5](STAGE5.md#5-особые-запуски-аванпост-лифт-гримфорджа-ясная-ночь-приют-вокин-рейтвин).
- **Фаза AD** (`ADStager`): текстовая реплика — `TLVoice` без звука длиной по тексту (14 знаков/с
  + 0,6 с, от 2,5 до 10 с) и эмоции из сценария; её озвученная реплика — `TLVoice` ванильной фазы,
  длина по голосу, её эмоции оттуда же.
- **Озвученная реплика из AD в главе** (глава 2, «I can't remember the last time I played like that» из
  `SCE_AD_Alfira`): у AD нет сцены, поэтому фаза строится по длине голоса, с шаблонной постановкой
  основы и стандартным планом (`staging.py`, `_voiced_from_ad`).

## 6. Известные ограничения

- **Реплики без озвучки.** У новых текстов нет голоса и движения губ; лицо двигают только
  ключи эмоций. Длительность — по объёму текста.
- **Озвученные реплики в чужой обстановке.** Постановка вырезана из сцен, где она стояла у
  костра (Темный Соблазн), сидела у камня (песня), в «Последнем свете». Камеры переведены на
  стандартные, локальные камеры тех сцен заменены. Свет — нейтральный свет основы.
- **Сидит она или стоит.** В Роще она сидит на своём камне (`Use(S_DEN_Bard, S_DEN_BardSeat)`),
  а основа — сцена «стоя». Ванильный разговор у камня тоже ставит ей позу стоя
  (`DIAG_Pose_Stand_R_Forward_01`), но как это выглядит с нашей сценой — проверить в игре.
- **Нет собственных анимаций, жестов и кат-сцен** — этап 9 (ROADMAP). Действия из ремарок
  сценария («подтягивает колени к груди», «стягивает сапоги») показываются ремаркой рассказчика
  (`narrate`), а поза остаётся позой основы — она стоит. Подходящей ванильной анимации
  «сесть у костра» для сцены стоя нет.
- **Основа сцены — одна: `DEN_Bard_InParty`.** Это её собственный ванильный разговор в лагере
  ночью (Темный Соблазн, ночь перед убийством), стандартная сцена `bnz_standing_Px1`. Ванильные
  лагерные разговоры спутников — главы Шэдоухарт (`ShadowHeart_InParty2_Nested_DefaultChapter`),
  первые ночи (`CAMP_Night1_CRD_Shadowheart`) — используют те же камеры `bnz_standing_Px1`
  (проверено по таймлайнам: 7 из 7 камер). Костёр, ночь и свет даёт сам лагерь, а не сцена.
  Взять основой чужой диалог (например, `CAMP_Night1_CRD_*`) генератор не умеет: он ищет Альфиру
  среди спикеров основы, а сцены CRD привязаны к месту и реквизиту конкретного спутника.
- **Женские формы** через `…_ru_to_F.xml`: суффикс `_to_F` в движке есть рядом с загрузчиком
  loca, но то, что игра применяет его к файлам мода, не проверено. Если в игре героине
  показывается мужская форма или мужчине женская — выключить `FEMALE_VARIANTS` в `build.py`.
  Небинарный герой (X) получает мужскую форму.
- **Скомпилированные снимки таймлайна** (`CompiledNodeSnapshots`) не пишутся — игра строит
  их при загрузке (так делает и bg3moddinglib для Really Shadowheart).
